# Viewer rules (from spike/FINDINGS.md)
- A muscle id maps to a list of GLB nodes, not one node (biceps = long head + short head). Each node exists as `<name>.l` and `<name>.r`.
- GLTFLoader sanitises node names (whitespace to `_`, strips `[ ] . : /`): `Latissimus dorsi muscle.r` becomes `Latissimus_dorsi_muscler`. Look nodes up with `getObjectByName(sanitize(name))`.
- A node with two primitives loads as a Group, so material changes must traverse it.
- Materials in the GLB are placeholders (`export_materials="PLACEHOLDER"`); the viewer assigns its own.
- Some node names are wrapped in parentheses, e.g. `(Abdominal part of pectoralis major muscle).l`; the parentheses are part of the name.
- The GLB is a CC BY-SA 4.0 derivative: both credit lines (Z-Anatomy CC-BY-SA 4.0, BodyParts3D CC-BY-SA 2.1 Japan) must stay in the page footer.
- The skeleton (`skeleton-draco.glb`) is decoration loaded into its own group: it is never raycast, highlighted or dimmed.
- `Muscle.view` ("front" | "back", hand-assigned) picks the side `focus()` turns the camera to (`targetAzimuth` in `camera.ts`); the camera animates azimuth/elevation/distance/target, never the position vector. Materials are assigned only in `refresh()` (selected, hover, dim, base).
- Picking is GPU-based (`pick()`: 1x1 render target, flat id colours, one per GLB part node (`part-pick.ts`, 8-bit red channel, capacity checked at load), so one pick answers both muscle and part; skeleton hidden for the pass; `onSelect`/`onContextSelect` still get the muscle id). The stalls that motivated it were measured in Rosetta-emulated Chrome; native Chrome handles the old raycast fine (see ADR 0006), so re-measure natively before changing pick() either way. `AtlasApi.preview(id|null)` is the sidebar hover preview: it yields to the pointer while it is on the canvas. `AtlasApi.onPartHover` reports the hovered part only when exactly one muscle is selected and it has more than one part; that part's `.l`/`.r` nodes are painted amber in `refresh()`, the others keep their section colour.
- `onFrame` hands out ONE reused `FrameInfo` (valid only inside the callback) built from cached surface anchors (`anchorForObject`, one limb side per muscle, 0.85 hysteresis); anchors for every muscle in `MUSCLES` are computed once at load, behind the loading overlay (about 15 ms in native Chrome). No raycasts or layout reads in that hook.
- `callouts.ts` draws one callout per part in `FrameInfo.parts` (the largest, capped at 6; `FrameInfo.parts[].index` is the `partsFor` index): a flat square swatch in the part's section colour (`sectionColor`, or the abdominal style colour), the cleaned part name (`calloutLabel` in `callout-parts.ts`: drops " of <muscle name>", parentheses, " muscle"), 1px underline, 1px leader line and a dot at the part anchor, placed left/right of the muscle by `layoutCallouts` (a part facing away is hidden and takes no room), pointer-events none. It never reads layout per frame: avoid rects (left rail, `#side` only while visible, view controls, brand, sources, chat panel) are cached (ResizeObserver) and the labels are measured on creation, on resize and when the layer turns on; `update` rebuilds them when `FrameInfo.id` changes and hides them on null; DOM writes happen only when the rounded value changes; positions are never CSS-transitioned. No part-hover emphasis. Hidden under 600 px.
- Left rail: the `Muscles` list is always visible and open (flat list, no collapse on selection, no `M` key). `Muscle building` and `Mixer` are collapsed `details` beneath it and form an accordion of two. Esc closes the dataset popover first, then deselects. Under 900 px the list is a horizontally scrolling row.
- `side-panel.ts`: right-hand `#side` (hidden with no selection; bottom sheet under 900 px) with the muscle name and two real tabs (`tablist`/`tab`/`tabpanel`, roving tabindex, Left/Right/Home/End; the tab survives a change of muscle). "Exercises": one plain list of exercise names, bodyweight first then loaded, no group headings and no separate Isolation list (one `aria-pressed` button each; the open row shows dataset Primary/Secondary groups via `datasetGroups`, a "Compound · Bodyweight" style line from mechanic and modality, and the verbatim quote), plus the "Dataset listing (i)" popover (a listing, not a ranking). "Anatomy and evidence" is `anatomyContent(id)` from `panel.ts`. DOM via `h()`, never innerHTML. With several muscles in the Mixer the panel shows the most recently selected one.
- Mixer: right-click (or Shift+Enter/Shift+Space) a list muscle, or right-click a mapped model muscle, to toggle it in the mix. Mixed groups remain highlighted together. Exact exercise overlap comes only from free-exercise-db primary/secondary region mappings; no overlap means no invented recommendation.
